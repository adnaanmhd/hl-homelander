<objective>
Gap closure for CR-01 (the mobile side of the CR-01/CR-02 pair). `UploadCoordinator.uploadOne()` currently re-POSTs `/recordings/init` (or `/recordings/:id/reupload`) on EVERY (re-)drain — even when `row.uploadId != null` and parts are already DONE. Each `/init` mints a brand-new S3 multipart `uploadId`, so the already-DONE parts' cached ETags belong to the now-orphaned prior `uploadId`; `/finalize` then sends a mix of old+new ETags → S3 `InvalidPart` → `IOException` → treated as transient → the row spins forever, never uploads, never dead-letters. Worse than a whole-file restart. This plan makes `uploadOne()` call the new `POST /recordings/:id/parts` re-presign route (Plan 05-09 — re-signs URLs against the EXISTING `uploadId`, no `CreateMultipartUpload`) on a re-drain, preserving the already-uploaded parts' ETags (UP-04, the slow-cellular resume guarantee — the documented India/Brazil target market). It also folds in WR-06 (don't leak presigned URLs into a log on a non-JSON response) since the change is in `parseInitResponse`'s neighbourhood.

Purpose: UP-01 (the upload survives a process-kill / presigned-TTL expiry — `/finalize` uses the upload id the client uploaded against, and a re-drain doesn't orphan anything), UP-04 (no whole-file restart — already-DONE parts keep their valid ETags).
Output: the re-presign branch + `postRePresign` + the hardened `parseInitResponse` in `UploadCoordinator.kt` + the Robolectric/MockWebServer test.
</objective>

1. validates the bundle files exist (missing → `DeadLetterException`);
2. `val isReupload = row.reupload`; pins `row.chunkBytes` / `row.partsCount` once; lays out `row.videoParts` (preserving any DONE ones) + `row.imuParts` (1 part);
3. `val initResp: InitResponse = if (isReupload) postReupload(baseUrl, row, partsCount) else postInit(baseUrl, row, jsonFile, partsCount)` — **THE BUG: always re-POSTs `/init` even when `row.uploadId != null`**;
4. `row.uploadId = initResp.uploadId; row.imuUploadId = initResp.imuUploadId; row.state = UPLOADING; queueStore.upsert(row)`;

7. wait on futures; a future's `DeadLetterException` cause → rethrow (dead-letter); a transient cause → rethrow (retry);
8. re-check every part is `DONE` + has an `etag`;
9. `row.state = FINALIZING; queueStore.upsert(row); postFinalize(baseUrl, row)`;
10. `row.state = AWAITING_VERIFY; row.reupload = false; queueStore.upsert(row); emitQueueChanged()`.

`drainNow()` catches: `DeadLetterException` → `row.state = DEAD_LETTER; row.deadLetterReason = e.message; queueStore.upsert(row); emitQueueChanged()`; any other `Exception` → `Log.w(TAG, "row ${row.recordingId} upload failed transiently: ${e.message}")` (no rethrow — the next drain retries).
