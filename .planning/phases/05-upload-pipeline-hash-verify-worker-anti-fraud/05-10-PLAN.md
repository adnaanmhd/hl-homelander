<objective>
Gap closure for CR-01 (the mobile side of the CR-01/CR-02 pair) plus the WARNING-4 re-drain residual the checker flagged. `UploadCoordinator.uploadOne()` currently re-POSTs `/recordings/init` (or `/recordings/:id/reupload`) on EVERY (re-)drain — even when `row.uploadId != null` and parts are already DONE. Each `/init` mints a brand-new S3 multipart `uploadId`, so the already-DONE parts' cached ETags belong to the now-orphaned prior `uploadId`; `/finalize` then sends a mix of old+new ETags → S3 `InvalidPart` → `IOException` → treated as transient → the row spins forever, never uploads, never dead-letters. Worse than a whole-file restart. This plan makes `uploadOne()` call the new `POST /recordings/:id/parts` re-presign route (Plan 05-09 — re-signs URLs against the EXISTING video + IMU `uploadId`s, no `CreateMultipartUpload`) on a re-drain, preserving the already-uploaded parts' ETags (UP-04, the slow-cellular resume guarantee — the documented India/Brazil target market). It also clears `row.reupload` immediately after `postReupload` so a re-drain of a re-upload that got process-killed mid-flight takes the `/parts` branch (preserving the re-upload's DONE parts' ETags) instead of calling `/reupload` again (which would orphan them — CR-01 on the re-upload path), maps a `409` from `/parts` (or from `/init`, post-CR-02-fix) to a `DeadLetterException` so a stuck row dead-letters instead of looping, and folds in WR-06 (don't leak presigned URLs into a log on a non-JSON response) since the change is in `parseInitResponse`'s neighbourhood.

Purpose: UP-01 (the upload survives a process-kill / presigned-TTL expiry — `/finalize` uses the upload id the client uploaded against, and a re-drain — including a re-drain of a re-upload — doesn't orphan anything), UP-04 (no whole-file restart — already-DONE parts keep their valid ETags).
Output: the re-presign branch + `postRePresign` + the `row.reupload` clear after `postReupload` + the `/init` 409→DeadLetter mapping + the hardened `parseInitResponse` in `UploadCoordinator.kt` + the Robolectric/MockWebServer tests.
</objective>
