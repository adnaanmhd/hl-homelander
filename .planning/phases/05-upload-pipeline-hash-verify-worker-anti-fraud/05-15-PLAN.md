<objective>
Close the single Phase-5 UAT blocker recorded 2026-05-13 in `05-HUMAN-UAT.md`
Gaps: on the post-Wave-1.5 build the `__DEV__` Tasks-tab long-press path drives
RecordingScreen → hand gate → `HumynCapture.start(opts)` (RecordingScreen.tsx:703)
and the Kotlin bridge rejects synchronously with `code=invalid_opts msg=invalid_opts: name`
at `CaptureSessionOptsBridge.kt:84` (`requireNonEmpty(contributorMap, "name")`).
The empty field is `contributor.name`, NOT `taskName`. Root cause is upstream:
`RecordingScreen.tsx:695` builds `user.name: u.user?.name ?? ''` from
`useAppStore.user.name` (which is `string | null` per `appStore.ts:51`), so any
signed-in user whose store `name` is null/empty (sign-in path didn't write a
name, Google withheld `displayName`, or `/me` rehydrated without one) emits `''`
into the bridge → the Kotlin guard fires → recording never starts → UAT items
2–5 stay pending downstream.

Purpose: Re-enable the Pixel-10a Phase-5 UAT re-walk by fixing the regression at
TWO layers — (1) propagate a non-empty name into the store at every sign-in /
`/me` write site (email-local-part fallback when Google's `displayName` is
absent), AND (2) add a JS-side `buildCaptureOpts` guard (parallel to the V11
`consentPresent` guard) so any future regression of the same shape surfaces
as a clear user-facing toast instead of an opaque bridge rejection. This
mirrors the project's established belt-and-suspenders pattern for trust-
boundary inputs (consent: JS guard + Kotlin guard). The Kotlin guard at
`CaptureSessionOptsBridge.kt:84` STAYS in place (T-3.3-01 defense-in-depth).

Output: `apps/mobile/src/lib/userDisplayName.ts` (new shared helper) + a JS-side
guard in `buildCaptureOpts.ts` (new code-typed Error) + propagation fixes at
the three `setUser` call sites (Signup / Profile / foreground rehydrate) + new
Vitest + Robolectric coverage + a runbook §1 pre-flight check confirming
the signed-in user has a non-empty store name before §2.

Sibling-field scope note: the UAT 2026-05-13 `missing:` block also flagged
`appVersion` (RecordingScreen.tsx:701, `appVersionRef.current`) for the same
`?? ''` anti-pattern. `appVersion` is OUT OF SCOPE for this plan — it is NOT
sourced from `useAppStore.user`; it comes from `readAppVersion()` (the
`AppFlavor` native module wraps `BuildConfig.VERSION_NAME`) bound into the
ref at module init, and its empty/malformed case is already guarded by the
SEMVER regex check at `CaptureSessionOptsBridge.kt:126-128`
(`SEMVER.matches(it)`). Different propagation path, different guard, different
failure mode — touching it here would be scope creep. `contributor.email`
(RecordingScreen.tsx:696) IS in scope (same JS-store-sourced propagation path
as `name`) and is covered by the Task-1 JS-side `requireNonEmpty` guard +
the Task-3 Robolectric empty-email test.

    ```typescript
    // userDisplayName — shared name-coalesce helper used by the three
    // `useAppStore.user.name` write sites (SignupScreen post-Google-Sign-In,
    // ProfileScreen post-/me, useForegroundUserRehydrate post-/me). Google's
    // `displayName` is null/empty for accounts that never set one; the
    // server's `users.name` is `text` and nullable for the same reason. Per
    // the 05-HUMAN-UAT.md Gaps entry (2026-05-13), the previous pattern of
    // `setUser({ name: result.user.name, ... })` propagated `null`/empty
    // straight into the store → `buildCaptureOpts` got `args.user.name = ''`
    // → the Kotlin bridge rejected with `invalid_opts: name` and recording
    // never started. This helper coalesces to the email-local-part (the part
    // BEFORE the `@`) when the upstream name is absent, mirroring the
    // common convention used by other consumer apps when Google withholds a
    // display name. If even the email-local-part is empty (a malformed
    // address that somehow survived sign-in), we return `null` and let the
    // buildCaptureOpts JS-side guard (code: 'profile_incomplete') surface
    // a clear user-facing toast at recording-start time.
    //
    // Trim semantics: a single whitespace-only `name` is treated as absent
    // (Google's `displayName` is occasionally ` ` for institutional
    // accounts); the email-local-part is also trimmed. NEVER throws — the
    // call sites use the return value directly in `setUser({ name: ... })`.

    export function coalesceDisplayName(
      name: string | null | undefined,
      email: string | null | undefined,
    ): string | null {
      const trimmedName = (name ?? '').trim();
      if (trimmedName.length > 0) return trimmedName;
      const trimmedEmail = (email ?? '').trim();
      if (trimmedEmail.length === 0) return null;
      const localPart = trimmedEmail.split('@')[0]?.trim() ?? '';
      if (localPart.length === 0) return null;
      return localPart;
    }
    ```
