<objective>
Gap closure for CR-02 (the server side of the CR-01/CR-02 pair) plus the residual lost-`201` retry loop the verifier flagged. `POST /recordings/init` is currently non-idempotent — it always `CreateMultipartUpload`s the video + IMU streams and `INSERT ... onConflictDoNothing()`, so a duplicate `/init` (the retry path the mobile coordinator takes on a process-kill / presigned-TTL expiry) leaves the row's `s3UploadId` as the FIRST one while the response binds to a SECOND fresh upload → `/finalize` 409s / `NoSuchUpload`s on the stale `s3UploadId` → the recording is permanently un-finalizable, and a stray multipart upload leaks per duplicate call. This plan makes `/init` SELECT-first + idempotent: a duplicate `/init` for an existing `pending` row owned by the caller re-presigns the video parts against the row's stored `s3UploadId` (no second video `CreateMultipartUpload`), issues a fresh `CreateMultipartUpload` on the IMU stream only (the IMU id was never persisted on the row, so it's the one stream that can't be re-presigned and must be restarted), and returns `200` with the SAME `uploadId` it returned the first time — which also self-heals the case where the first `/init`'s `201` is lost before the client persists `row.uploadId` (the next drain re-calls `/init`, gets the existing id back, proceeds — no infinite loop). It also adds a `POST /recordings/:id/parts` re-presign route (no `CreateMultipartUpload` of any kind, no state change) that the mobile coordinator (Plan 05-10) calls on a re-drain instead of `/init` — preserving the already-uploaded VIDEO **and** IMU parts' ETags (the slow-cellular resume guarantee, UP-04).

Purpose: UP-01 (the upload lifecycle survives retries — `/finalize` always uses the upload id the client uploaded against; a duplicate `/init` never strands the row), UP-04 (no whole-file restart — already-DONE parts keep their ETags because the video upload id never changes). This is the **server half**; the mobile coordinator's "call `/recordings/:id/parts` on a re-drain instead of re-`/init`" change is Plan 05-10 (wave 2, depends on this route existing).
Output: an idempotent `init.ts` + the new `parts.ts` route + the route registration + the new shared-types schemas + the two Vitest specs.
</objective>
