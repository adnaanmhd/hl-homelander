## Trust Boundaries

| Boundary                                    | Description                                                                                                  |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| client → API (`/reupload`, `/verified-ids`) | a `recording_id` in the path crosses here — could be forged to target another user's recording               |
| API response → client (`_events` envelope)  | the `_events` payload leaves the server — must carry only the requesting user's recording ids                |
| S3 → EventBridge → SQS → worker (prod)      | the bucket-event → queue path; the EventBridge rule + the SQS queue policy + the worker IAM are the controls |
| worker ECS task → S3 / SQS / Redis / RDS    | the worker's task role — must be least-privilege (S3 read-only, SQS receive/delete, no bucket writes)        |
