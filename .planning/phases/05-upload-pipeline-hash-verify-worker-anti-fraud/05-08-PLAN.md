## Trust Boundaries

| Boundary                                                                                 | Description                                                                                                                                              |
| ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API response → app (`_events` envelope)                                                  | the `_events` payload arrives from the server — the app must validate the shape and only act on `(recording_id, event_type)` it can map to its own queue |
| app → device FS (deleting local recordings)                                              | the `verified` handler + the reconciliation sweep unlink the local triple — the path must be recomputed locally, never received                          |
| RN ↔ native (`HumynUpload.clearVerified` / `reupload` / `enqueue` / `pause` / `resume`) | JS drives the native module — args (`recording_id`, paths, `ownerUserId`) come from the app's own state, not a server-supplied path                      |
| screen ↔ navigator                                                                      | a `Pressable` navigates to `'PendingUploads'` — local nav, no input                                                                                      |

| Threat ID | Category                   | Component                                                                                              | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------- | -------------------------- | ------------------------------------------------------------------------------------------------------ | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-5-08-01 | Tampering                  | a replayed/forged `verified`/`re-upload` `_events` payload causing a double-delete or a re-upload loop | mitigate    | `processRecordingEvents` validates the shape (26-char `recording_id`, `event_type ∈ {verified,re-upload}`) and de-dups on `${recording_id}:${event_type}` in the shared MMKV `UPLOAD_PROCESSED_EVENTS` set — a redelivered event is a no-op; `clearVerified` is convergent (it only unlinks files for a recording the app already has queued); a re-upload loop self-limits via the client's retry budget (the row dead-letters → `chip-failed`). |
