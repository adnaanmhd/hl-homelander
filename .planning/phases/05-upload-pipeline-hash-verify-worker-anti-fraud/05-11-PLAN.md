<objective>
Gap closure for CR-03 (the drain-serialisation defect). `UploadCoordinator.drainNow()` is `public` and invoked DIRECTLY off three threads with no mutual exclusion — `HumynForegroundService.startUploadDrain()` on its own HandlerThread, `UploadJobService.onStartJob()` on a freshly `start()`ed Thread, and `HumynUploadModule.drain()` via the `drainExecutor`. They can run `uploadOne(row)` on the same row simultaneously: each re-POSTs `/recordings/init` (compounding CR-01/CR-02 — process-kill is exactly when the FGS thread + a UIDT-job thread can both fire), each lays out `row.videoParts`, each writes the shared mutable `row` back, and `row.uploadId` is overwritten by whichever finishes last. The `synchronized(queueStore)` inside `uploadOne` is on a DIFFERENT monitor than `UploadQueueStore.upsert()`'s private `lock`, so it serialises nothing. The "only one drain at a time" invariant the whole design depends on is unenforced. This plan adds a `private val drainLock = ReentrantLock()` guarding `drainNow()`'s body with `tryLock()` (a second drain just returns), drops the bogus `synchronized(queueStore)` wrappers (a bare `queueStore.upsert(row)` is already self-synchronised), and confirms DEF-5-01 is closed (the Robolectric test module compiles — fixed in Plan 05-01) so the new tests can run.

Purpose: UP-06 (uploads survive backgrounding / force-quit — the FGS / UIDT-job / module drains can't corrupt each other's state on a process-kill recovery), UP-01 / UP-04 (the single-drain invariant is a prerequisite for the CR-01 fix in Plan 05-10 — two concurrent re-presigns would still race). This is the **unblocker** for the force-quit-recovery on-hardware smoke test (recorded as a human-verification item in `05-VERIFICATION.md`).
Output: the `drainLock` + the dropped `synchronized(queueStore)` wrappers in `UploadCoordinator.kt`, a one-line `withLock` helper on `UploadQueueStore` only if needed, the DEF-5-01 re-verify (likely a no-op), and a concurrency test.

## Trust Boundaries

| Boundary                                                                                      | Description                                                                                                                                                                               |
| --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FGS HandlerThread / UIDT-Job Thread / `drainExecutor` thread → `UploadCoordinator.drainNow()` | three in-process threads all call the same singleton's `drainNow()` — no external input; the only correctness boundary is mutual exclusion (the design's "one drain at a time" invariant) |
| concurrent part-PUT futures (one drain) → `UploadQueueStore.upsert(row)`                      | the 6-permit semaphore lets several part futures `upsert(row)` near-simultaneously — must be serialised at the store level (the store's own `lock`)                                       |
