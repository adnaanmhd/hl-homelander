<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer machine ↔ git | Pre-commit hook is the only enforcement layer between un-linted code and committed code; can be bypassed with `--no-verify` |
| pnpm registry ↔ local node_modules | Untrusted package code (transitive deps) executes during `pnpm install` and on import |
| repo ↔ CI keystores | `.gitignore` is the only barrier preventing keystores from leaking into commits |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1.1-01 | Tampering | `.husky/pre-commit` bypass via `--no-verify` | low | accept | Per CLAUDE.md "GSD Workflow Enforcement"; CI re-runs lint+typecheck on every PR (later plan adds CI). Bypass at commit is acceptable; CI is the hard gate. |
| T-1.1-02 | Tampering | Malicious transitive dependency (supply-chain) | medium | mitigate | All versions pinned (no `^`/`~` carets) in apps/api/package.json so resolution is deterministic. Any change requires explicit version bump + PR review. Locked from upstream — versions match RESEARCH.md Standard Stack. |
| T-1.1-03 | Information disclosure | Keystore committed by mistake | high | mitigate | `.gitignore` includes `apps/mobile/android/keystores/` (Task 1). `.gitattributes` marks `*.{jks,keystore}` as binary so even forced commits are visible. CI lint step in plan 09 will add a hard gate. |
| T-1.1-04 | Information disclosure | `.env` committed by mistake | high | mitigate | `.gitignore` includes `.env`, `.env.local` (Task 1). Per-flavor `.env.${flavor}` files in plan 09 follow the same exclusion. |
| T-1.1-05 | Denial of service | `pnpm install` fails on Node version mismatch | low | mitigate | `engines.node` in root package.json + `.nvmrc` declare Node 22; pnpm refuses to install on mismatch. |

No `severity: high` threats remain unmitigated.
</threat_model>
