### Gaps Summary

Phase 4 landed an enormous amount of substantive, well-formed code — the §4.3 state machine, the 5 recording UI components, the live VisionCamera mount + hand-gate poll loop, the 5 Kotlin native modules (HandDetector / PhoneState / Battery / ScreenBrightness / Beep, all correct by inspection), the `useRecordingLifecycle` §10 policy table, the practice/tutorial screens, the per-account ONB-08 gate, the crash-recovery toast, the manual-smoke runbook, and 572 green tests. But **one statically-verifiable code defect (CR-01) makes the entire recording surface unreachable in any non-`__DEV__` build**: nothing dispatches `LANDSCAPE_DETECTED` outside the `{__DEV__ ? ... : null}`-gated "Pretend I rotated →" pill, and `useRecordingLifecycle`'s orientation listener handles only the portrait→stop case, never landscape→advance. In a release build the surface is stuck on the inert `rotate-prompt` body forever — so the hand-gate, the recording, the practice tutorial, and (because `computeInitialRoute` keeps routing new users to `RigTutorial` until `PracticeComplete` runs) the new-user path to `MainTabs` are all unreachable. The phase goal is not achieved in production.

Two further reliability gaps in the recording surface: **WR-01** — the HAND-11 RemoteConfig `consecutive_hits_required`/`cadence_ms` keys are read by `readGateConfig()` but never dispatched into the reducer, so they're inert (only `min_hand_detection_confidence` is live; HAND-11 is ~⅓ delivered, and the per-segment metadata records the hard-coded `5/400` regardless of RemoteConfig); **WR-02** — exiting (X or background) during the gate→record handoff orphans the native capture session + foreground service because no exit path calls `HumynCapture.stop()`. WR-03/WR-04/WR-05/WR-07 are additional warnings (HandDetector cleanup race; SoundPool first-tone-silent; the unvalidated `SETTLE_MS=80` on the ±1 ms-critical path; practice 60 s cap overrun via the stop-confirm modal).

**Root cause grouping:** the three actionable gaps are independent (CR-01 = missing orientation→dispatch wiring; WR-01 = RemoteConfig values not threaded to the reducer; WR-02 = missing `HumynCapture.stop()` on exit). CR-01 is the only phase-goal blocker; WR-01 and WR-02 are reliability/correctness gaps that should be closed in the same pass since they live in `RecordingScreen.tsx`.

**No items are deferrable** — none of these gaps are addressed by a later milestone phase (Phase 5 is the upload pipeline; Phase 6 is Tasks/History/Home; Phase 7 is observability + APK distribution). All belong to Phase 4's contract.
