<threat_model>

## Trust Boundaries

| Boundary                                               | Description                                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| JWT (already-verified, from sign-in) → local cache key | the `sub` claim is decoded without re-verifying the signature, to derive an MMKV key |
| MMKV (device-local) → boot routing                     | the per-account flag controls whether the tutorial re-runs                           |

## STRIDE Threat Register

| Threat ID | Category                           | Component                                      | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                                              |
| --------- | ---------------------------------- | ---------------------------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-4.3-01  | Spoofing / trust of unsigned claim | `decodeGoogleSubFromJwt` used for the MMKV key | mitigate    | decode-without-verify is acceptable ONLY because the JWT was already verified at sign-in and `sub` is used solely as a local cache key — never as an authorization decision. The util's docstring states this; ASVS V2/V6 disposition: accept (no authz impact). Reuse the existing decode util (don't hand-roll base64url). |
| T-4.3-02  | Business-logic bypass              | the ONB-08 once-per-install gate               | accept      | reinstall legitimately re-runs the tutorial (intended ONB-08 semantics, not a bypass); a same-device re-login with the same `sub` does NOT re-run (the flag persists). This is the spec.                                                                                                                                     |
| T-4.3-03  | Information disclosure             | logging the JWT / `sub`                        | mitigate    | `setPracticeDone` / `computeInitialRoute` MUST NOT log the JWT or the decoded `sub` (Crashlytics breadcrumbs, analytics props). No log statements added in this plan.                                                                                                                                                        |

</threat_model>
