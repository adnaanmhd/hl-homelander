<threat_model>

## Trust Boundaries

| Boundary                                                                         | Description                                                                                       |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Route param `recordingId` → `getRecordingStreamUrl` → /recordings/:id/stream-url | recordingId is ULID-shaped; server validates length + ownership                                   |
| `getRecordingStreamUrl` response → `HumynPlayer.prepare(presignedUrl)`           | URL signed by CloudFront-signer server-side; client passes through                                |
| Local file resolution → `HumynPlayer.prepare(file://<filesDir>/...)`             | filesDir is app-private (Linux DAC); the URI scheme gate in Plan 06-06 PlayerController validates |
| Player events → onError code/msg                                                 | Server / device error codes only; no PII                                                          |

## STRIDE Threat Register

| Threat ID | Category                   | Component                                                             | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                           |
| --------- | -------------------------- | --------------------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-6.10-01 | I (Information Disclosure) | PlayerScreen sources URI from local ledger that survived logout/login | accept      | Per Pitfall 8 (Plan 06-04), the ledger is NOT user-scoped; same-user logout/login preserves entries. The server-issued ULID gates remote playback (cross-user → 404). For local file:// playback, the file IS on-device under filesDir — bytes never leave; the user owns them. Accepted. |
| T-6.10-02 | T (Tampering)              | Route params recordingId injected via deep-link                       | mitigate    | Plan 06-06's `PlayerController.validateUriScheme(...)` gate rejects file:// outside filesDir. getRecordingStreamUrl server-side validates the ULID format + ownership. Both walls fire.                                                                                                   |
| T-6.10-03 | I (Information Disclosure) | Cached presignedUrl persists beyond TTL                               | mitigate    | URL TTL = 5 min (Plan 06-03). On unmount or X-close, the ExoPlayer is released — the URL is not retained beyond the screen lifetime. The "Link expired. Tap to refresh." retry state re-fetches a fresh URL.                                                                              |
| T-6.10-04 | D (DoS)                    | Rapid mount/unmount leaks ExoPlayer codec resources                   | mitigate    | `HumynPlayer.release()` is called on unmount (useEffect cleanup) AND `HumynPlayerModule.invalidate()` (Plan 06-06) releases on JS module teardown. Idempotent.                                                                                                                            |
| T-6.10-05 | S (Spoofing)               | Player route opened without going through HistoryRow                  | accept      | Deep-linkability requires opening Player with valid `recordingId` route params. Without HistoryRow context, the screen mounts and resolves via server stream-url — server-side auth + 404 are the trust boundary.                                                                         |
