# Quick Task 260510-002: progress-event-driven CompatRunningScreen

## Background

The probes run serially in `runCompatCheck`:

| #   | Probe                       | Real duration            | Rows it determines                                        |
| --- | --------------------------- | ------------------------ | --------------------------------------------------------- |
| 1   | `runEncoderProbe()`         | ~1-3s (encode test)      | integrity (b-frames, OIS, HDR) — partial                  |
| 2   | `runImuProbe(30_000, true)` | **30s by spec** (LOCKED) | motionSensors, imu                                        |
| 3   | `readDeviceCaps()`          | <1s                      | ultrawide, resolutionFps, mic, realtime, integrity (root) |

The current `CompatRunningScreen` runs a fixed 700 ms-per-row cosmetic walk that:

1. Completes its 7-row sweep at ~4.9 s (well before the IMU probe finishes).
2. Speculatively flips rows 1-6 to ✓ regardless of real outcome.
3. Leaves the integrity row stuck on the `⋯` glyph for the remaining ~28 s.
4. Misleads the user into believing "device integrity" is the long-pole, when actually the IMU sustained-sampling window is.

The right fix: tie row state and percent ring to actual probe lifecycle events.

## Design

### Step 1 — `compatService.ts`: emit progress events

Add an optional `onProgress` callback. Events fire BEFORE and AFTER each native probe so the screen can transition rows in lock-step with reality.

```ts
export type CompatProgressEvent =
  | { phase: 'encoder'; status: 'started' }
  | { phase: 'encoder'; status: 'completed'; result: EncoderProbeResult }
  | { phase: 'imu'; status: 'started' }
  | { phase: 'imu'; status: 'completed'; result: ImuProbeResult }
  | { phase: 'deviceCaps'; status: 'started' }
  | { phase: 'deviceCaps'; status: 'completed'; result: DeviceCapsResult };

export async function runCompatCheck(
  onProgress?: (e: CompatProgressEvent) => void,
): Promise<CompatResult> { ... }
```

Backward-compat: callers without `onProgress` see no behavior change. Tests pass without modification.

The native probe duration MUST stay at 30 s — D-COMPAT-05 LOCKED.

### Step 2 — `CompatRunningScreen.tsx`: event-driven row state machine

Replace the 700 ms-per-row interval with a state machine driven by probe events. State per row: `'pending' | 'running' | 'pass' | 'fail'`.

Row → probe dependency:

| Row           | Determining probe(s)   |
| ------------- | ---------------------- |
| ultrawide     | deviceCaps             |
| resolutionFps | deviceCaps             |
| motionSensors | imu                    |
| imu           | imu                    |
| mic           | deviceCaps             |
| realtime      | deviceCaps             |
| integrity     | encoder AND deviceCaps |

Transitions:

- `encoder.started` → integrity → 'running' (encoder is the first probe affecting integrity)
- `encoder.completed` → integrity stays 'running' (still needs deviceCaps for `root`)
- `imu.started` → motionSensors, imu → 'running'
- `imu.completed` → motionSensors, imu → real pass/fail from imu result
- `deviceCaps.started` → ultrawide, resolutionFps, mic, realtime → 'running'
- `deviceCaps.completed` → all caps-dependent rows resolve; integrity now resolves (encoder + caps both available)
- Final `runCompatCheck` resolution → final row sweep via `rowsFromResult(result)` (authoritative — same logic that drives CompatPass/Fail screens)

Percent ring drive:

- 0% on mount
- 5% on `encoder.started`
- 15% on `encoder.completed`
- 15% → 85% animated over a 30 s window during the IMU phase (smooth motion via setInterval @ 250 ms ticks)
- 90% on `imu.completed`
- 95% on `deviceCaps.started`
- 100% after final result + 400 ms hold (existing pattern).

- **DO NOT** change `runImuProbe(30_000, true)` to a shorter duration. The 30 s sustained-sampling window is LOCKED by capture spec D-COMPAT-05 (`idea-brief.md §2.1`). If you find yourself wanting to "speed up" the screen by shortening the IMU probe, STOP — the visual-feedback fix lives entirely in the screen layer.

- **DO NOT** remove the 7 `compat-row-{key}` accessibility labels — they're the test contract.
- **DO NOT** restructure `rowsFromResult` — final-result row mapping stays authoritative there. The screen's per-event handler is a streaming preview that converges to `rowsFromResult(result)` at probe completion.
