## Patterns introduced

**Pattern 59 — progress-event-driven UI for variable-duration multi-probe sequences.** When a UI shows row-by-row progress for a sequence of native probes whose durations vary widely (here: encoder ~2s, IMU 30s, deviceCaps <1s), drive the row states from per-probe lifecycle events rather than a fixed cadence. Service-layer signature: optional `onProgress` callback emitting `{ phase, status: 'started' | 'completed', result? }` events; listener errors are swallowed defensively (UI state must never reject the underlying operation). Screen-layer pattern: maintain accumulated-results ref, transition row states on each event, recompute cross-probe rows (e.g., integrity needs encoder + caps) from the accumulated state. Smooth-fill the percent ring across the dominant probe's window via setInterval-based interpolation. Reusable for any future Phase 5+ surface that orchestrates multiple long-running native operations (multi-segment uploads, batch hash-verify, etc.).
