# Quick Task 260510-005: Profile UX cluster

## Root causes

### Bug 1 — Head "tap to edit" caption is decorative

`apps/mobile/src/screens/profile/ProfileScreen.tsx:177-184`:

```tsx
<View style={styles.nameBlock}>
  <Text variant="bodyLg" style={styles.nameText}>
    {me.name}
  </Text>
  <Text variant="caption" tone="tertiary">
    tap to edit
  </Text>
</View>
```

Plain `<View>` — no `Pressable`. Tapping the head Name does nothing. The actual editable Name field lives in the Personal Info section below (`InlineEditField` row), which IS pressable, but the head's caption misleads users into expecting head-level edit.

**Fix:** wrap the head's nameBlock in a Pressable. On press, the head transforms inline into a `TextInput` (auto-focused). Blur saves via the existing `saveField('name', ...)`. The "tap to edit" caption becomes accurate.

### Bug 2 — Gender field is a free-text input; user wants a 3-option enum

`ProfileScreen.tsx:227-231` uses `InlineEditField` for Gender, which renders a TextInput. The user wants the choices constrained to: **Male / Female / Don't want to disclose**.

Backend acceptance: `apps/api` `UserPatchSchema.gender = z.string().max(40).nullable().optional()` — accepts any short string. So changing the mobile UI to send a constrained enum string is server-compatible without backend changes.

**Fix:** extend `InlineEditField` with an optional `options?: string[]` prop. When provided, the row's edit-mode shows a small Modal with one Pressable per option. Tap an option → save via `onSave` and close the modal. Free-text mode (TextInput) stays untouched as the default.

### Bug 3 — Home TopBar shows generic avatar; Profile shows Google photo

`apps/mobile/src/components/TopBar.tsx` accepts only `avatarInitial?: string` (defaults to `'U'`). It has no `avatarUrl` prop, so `HomeSkeletonScreen` (which calls `<TopBar onAvatarPress={...} />` without any user data) renders the fallback initial.

`ProfileScreen` separately fetches `/me` and renders `<Image source={{ uri: me.avatarUrl }} />` for its own avatar — that's why Profile's avatar works but Home's doesn't.

**Fix (3-step):**

1. Add a `user` slice to `appStore`. Shape: `{ id, email, name, avatarUrl } | null`. Actions: `setUser(u)`. `signOut()` clears it.
2. `SignupScreen` calls `setUser(result.user)` immediately after `signInWithGoogle()` resolves (alongside `setJwt(result.jwt)`). `ProfileScreen` calls `setUser(...)` after `/me` resolves so backend updates flow into the cache.
3. `TopBar` gains an `avatarUrl?: string` prop. When present, renders `<Image source={{ uri }} />`; otherwise falls back to the initial. `HomeSkeletonScreen` reads `useAppStore(s => s.user)` and passes `avatarUrl + avatarInitial` to TopBar.

**Existing-session caveat:** users already signed in before this fix lands have no user data in the store. They populate by visiting Profile once (Profile's `/me` fetch writes through to the store). Document in SUMMARY; verification step covers this.
