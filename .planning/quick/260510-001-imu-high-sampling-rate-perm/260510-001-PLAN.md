# Quick Task 260510-001: HIGH_SAMPLING_RATE_SENSORS for IMU probe

## Root cause (empirically confirmed via [COMPAT_DEBUG] instrumentation)

`apps/mobile/android/app/src/main/java/ai/humynlabs/capture/compat/ImuProbe.kt:57` calls `SensorManager.registerListener(..., samplingPeriodUs=0)` (fastest available). Starting Android 12 / API 31, requesting sensor sampling above 200 Hz requires the **`android.permission.HIGH_SAMPLING_RATE_SENSORS`** manifest permission (a "normal" permission — declaration only, no runtime grant).

Without it, `registerListener` throws `SecurityException`: `"To use the sampling rate of 0 microseconds, app needs to declare the normal permission HIGH_SAMPLING_RATE_SENSORS."` The IMU probe rejects → `runCompatCheck` bubbles up → CompatRunningScreen's `.catch` routes to CompatFail with no result → empty fail screen.

Pixel 10a (Android 16, API 36) is well above the 200 Hz threshold trigger. This will affect ALL Android 12+ devices in the field.

This should have been caught by Phase 1 plan 01-13 + Phase 2 plan 02-15, but both were `code-ready-smoke-deferred` so the IMU probe never ran end-to-end on a real Android 12+ device until this smoke walk.
