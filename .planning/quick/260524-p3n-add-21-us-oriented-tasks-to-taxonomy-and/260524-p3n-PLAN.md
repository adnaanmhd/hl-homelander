From `apps/api/scripts/parse-taxonomy.ts` (parser hard rules):

- Markdown table columns (in order): `| Category | Task | Setting | Description | Instructions |`
- `Setting` must lowercase to `indoor` | `outdoor` | `either` — otherwise the parser throws.
- `Instructions` cell is split on `<br>` (case-insensitive, optional self-close); each segment has leading `• ` / `* ` / `- ` / `\d+. ` stripped.
- Per-task instruction count: 1 ≤ N ≤ 3. >3 throws.
- Description must be non-empty; throws otherwise.
- Rows with fewer than 5 cells are silently skipped (do NOT rely on this — write full rows).
- `normalizeName()` strips a trailing `(...)` group before joining taxonomy ↔ mapping. So `Brewing single-cup coffee (pod machine)` in taxonomy joins to `Brewing single-cup coffee (pod machine)` in mapping (exact match wins; parenthetical-strip is only the fuzzy fallback).

From `apps/api/scripts/seed-tasks.ts`:

- `TAXONOMY_PATH = REPO_ROOT/task-taxonomy.md`
- `ICON_MAPPING_PATH = REPO_ROOT/design-system/task-icons/mapping.json`
- Requires `process.env.DATABASE_URL` — exits 1 if missing.
- Per-row: `embed(buildEmbeddedText({name, description, category}))` then `INSERT … ON CONFLICT (slug) DO UPDATE SET (every column)`.
- Embedder is in-process (`../src/lib/embedder.js`); if the embedder fails to load weights, the seed throws — that surfaces as a stack trace, not a row count.
