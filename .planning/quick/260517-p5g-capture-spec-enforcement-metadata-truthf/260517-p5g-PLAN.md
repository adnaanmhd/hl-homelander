<objective>
Gate uploads on actual capture quality (mean FPS ≥ 28, resolution ≥ 1080p) and
replace every hardcoded spec value in the segment metadata JSON with measured /
probed / reported values. Android only — iOS native modules remain deferred.

Purpose: the LOCKED capture spec is the project's core value (`CLAUDE.md` Core
Value banner — "if 1080p/30/≥110°/≥100 Hz slips, the project fails"). Today the
finalizer doesn't measure FPS and the metadata composer hardcodes every spec
field (`resolution`, `fps`, `bitrate`, `gop`, `b_frames`, etc.) regardless of
what was actually encoded. An OEM-throttled / thermally-degraded segment uploads
with truthful-looking metadata and silently poisons training. This plan makes
the finalizer the truth-teller: if the segment didn't hit spec, it never
uploads; if it did, every field in the JSON is what the encoder + extractor
actually reported.

Output:

- FinalizeWorker FPS + resolution gates (mean_fps < 28 → cancel; MP4 header w<1920|h<1080 → cancel; N<2 → cancel).
- EncoderProbe tightened to verify 1920x1080 SURFACE deliverability (not just codec presence).
- MetadataComposer: every spec-relevant field derived from EncoderReport (encoder OUTPUT_FORMAT_CHANGED MediaFormat snapshot) + VideoReport (MediaExtractor track-header read) + measured rotation.
- New native event `onSegmentCanceled` + JS bridge type + RecordingScreen handler that writes a History-row ledger entry, deletes the bundle files, and SKIPS HumynUpload.enqueue.
- UploadQueueStore defensive short-circuit + a Pending-Uploads guard so a malformed call can't render a canceled row.
- HistoryRow Canceled chip with three copy variants (re-uses Failed visual treatment).
- Updated REQUIREMENTS.md (CAPTURE-QA-01..06), STATE.md (decision log + Deferred Items), CLAUDE.md (banner under Constraints LOCKED).
- Tests at every gate: FinalizeWorker FPS/resolution/insufficient-frames branches, MetadataComposer literal regression guard, History/Pending Uploads cancel-row rendering.
  </objective>
