# Quick Task 260510-004: logout reset + Help Center markdown

## Root causes

### Bug 1 — LogoutModal nav.reset targets a non-sibling route

`apps/mobile/src/components/LogoutModal.tsx:33` calls:

```ts
nav.reset({ index: 0, routes: [{ name: 'Signup' }] });
```

`Signup` is **inside** `OnboardingStack` (an inner stack), not a sibling of `LogoutModal` at the root. RootNativeStack's siblings are `OnboardingStack`, `Main`, `Profile`, `HelpCenter`, `ForceUpgrade`, `LogoutModal`, etc. — `Signup` is not one of them. React Navigation silently drops the reset (no exception, no nav transition); from the user's perspective "nothing happens".

`signOut()` itself runs fine (clears MMKV + Zustand), but the user stays on the modal scrim.

**Fix:** target the OnboardingStack as the sibling route. `OnboardingStack` registers `Signup` as its first/initial screen, so resetting to it lands the user on Signup.

```ts
nav.reset({ index: 0, routes: [{ name: 'OnboardingStack' }] });
```

### Bug 2 — Help Center renders body strings as raw markdown

`apps/mobile/src/screens/help/HelpCenterScreen.tsx`'s `renderAccordion` passes `it.body` / `it.answer` / `it.resolution` directly into `<Text>` primitives. The strings come from `content.json` baked from `help-center-content.md` and contain markdown:

- `**bold**` (e.g. `**Tasks**`, `**Pending uploads**`, `**60 seconds**`, `**DELETE**`, `**30 days**`)
- `_italic_` (e.g. `_"Recording started."_`)
- ` `code` ` (e.g. `` `[EMAIL_ADDRESS]` ``)
- `-` bulleted lines
- `1.` ordered list lines
- `\n` line breaks within block strings

`<Text>{string}</Text>` renders the raw asterisks/underscores/backticks. The user sees `**Tasks**` instead of **Tasks**.

**Fix:** add a small markdown renderer at `apps/mobile/src/screens/help/markdown.tsx` that:

1. Splits the input into block-level chunks (paragraphs / bullet lists / ordered lists), grouping consecutive `-` lines and consecutive `\d+\.` lines.
2. For each block, parses inline tokens (`**`, `_`, `` ` ``) into segments and emits styled `<Text>` ranges via the existing `Text` primitive.

Wire into the three call sites (`it.body`, `it.answer`, `it.resolution`) plus the contact-support body.

No new dependency — the markdown subset is tiny and hand-curated; a pure-TS parser keeps the bundle clean and avoids New-Arch/library-maintenance risk.

**Action:**

1. New module `markdown.tsx` exports `<Markdown source={string} />`. Internals:
   - `parseBlocks(s: string): Block[]` where `Block = { kind: 'paragraph' | 'unordered' | 'ordered'; lines: string[] }`. Split on `\n`; consecutive `^- ` lines collapse into one `unordered`; consecutive `^\d+\. ` lines collapse into one `ordered`; everything else is `paragraph` (consecutive non-empty paragraph lines join with a space).
   - `parseInline(line: string): Segment[]` where `Segment = { kind: 'text' | 'bold' | 'italic' | 'code'; text: string }`. Regex tokenisation in priority order: `**…**` → bold, `_…_` → italic, `` `…` `` → code, residual → text.
   - Render: each block as a `<View>` with appropriate margin/padding; bullet rows show `•` glyph + inline; ordered rows show `1.` numeric + inline. Inline segments rendered as nested `<Text>` ranges with the token's style (bold uses `fontWeight: '700'`, italic `fontStyle: 'italic'`, code uses monospace family + slight bg via `colors.line` — check tokens.ts for an existing code background; if absent, use `colors.bg` darkened OR keep code as monospace-only).
2. HelpCenterScreen: replace `<Text variant="body" tone="secondary" style={styles.subsectionBody}>{it.body}</Text>` with `<Markdown source={it.body} />`. Same for `it.answer`, `it.resolution`. Also `content.contactSupport.body` if it has markdown.
3. Tests cover: bold/italic/code inline, bullet list, ordered list, mixed paragraph, line-break, the literal contact-support example with `[EMAIL_ADDRESS]` placeholder.

- **DO NOT** change the `[EMAIL_ADDRESS]` placeholder in this task — that substitution still belongs to the Phase 3 W1 cleanup (OQ-1, see `02-COSMETIC-GAPS.md`).
- **DO NOT** touch the cosmetic-backlog files: `apps/mobile/src/screens/signup/SignupScreen.tsx`, `apps/mobile/src/ui/primitives/Text.tsx`.
- **DO NOT** introduce new color hex literals in `markdown.tsx` — code-segment background must come from `tokens.ts` (existing tokens or a tiny new entry).
- The markdown parser is purposefully restricted to the subset the help content actually uses — do NOT generalise to full CommonMark; that's a Phase 5+ concern if we ever need user-authored markdown.
