## Patterns introduced

**Pattern 61 — root-sibling reset over nested-route reset.** In a React-Navigation tree where modals are registered as siblings of inner stacks, a `nav.reset({ routes: [{ name: 'X' }] })` from inside the modal can ONLY target sibling routes. Nested screens (e.g. `Signup` inside `OnboardingStack`) are silently dropped — no exception, no transition. The reset target must name the sibling stack and rely on its `initialRouteName` (or first child) to land the user on the desired screen. Future work: when adding a new logout-style flow that exits to an onboarding-flavoured screen, target the parent stack name, not the inner screen name.

**Pattern 62 — minimal-subset markdown renderer for hand-curated content.** When app content is markdown-authored but the rendering target needs only a small subset (no links, headings, code blocks, tables), a custom 50-line parser beats a third-party library. Benefits: zero dependency churn, zero New-Arch compatibility risk, exact-fit bundle size, easier unit-testing of edge cases. Defensive parsing (unmatched delimiters fall through as literal text) prevents a single authoring typo from blanking the rest of a line. Reusable for Phase 5+ surfaces that ship pre-baked content (e.g. tutorial scripts, payout breakdowns).

**Anti-pattern recorded: smoke-deferred plans whose tests mock too much.** Plans 02-18 (Help Center) and 02-19 (Logout) shipped as `code-ready-smoke-deferred`. Their unit tests mocked the navigator + the screen's child components — so the LogoutModal test asserted `nav.reset` was called with `'Signup'` but never validated that 'Signup' is reachable from the root navigator's hierarchy. Fix going forward: when an integration concern (route reachability, content rendering pipeline, real fetch) is critical, add at least one test that exercises the real wiring. Same recommendation as Pattern 60 (apiClient bearer attachment).
